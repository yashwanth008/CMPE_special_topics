# Assignment 5 - Recursive Self-Improvement, three methods on one problem

**Problem:** a self-improving *recipe-ingredient-line parser* (`"1½ cups flour, sifted"` → `(1.5, cup, flour)`).
RSI improves the parser's **source code**; every score comes from actually executing it on exact-match data.

**Methods implemented (arXiv abstracts verified 12 Nov 2026):**

| # | Method | Paper | What it changes |
|---|---|---|---|
| 1 | **Budget RSI** - score code edits before running them | [2610.29121](https://arxiv.org/abs/2610.29121) | which edit gets evaluated |
| 2 | **SO-RSI** - diagnose *why* failures recur before patching | [2610.05701](https://arxiv.org/abs/2610.05701) | the improvement workflow |
| 3 | **Self-HPO** - alternate harness and policy optimisation | [2610.22791](https://arxiv.org/abs/2610.22791) | harness *and* policy |

All 17 codelabs of **Section 10 · Research Studio** (labs 10.01-10.17) are implemented, including RSIFlow-style routing, AReaL-style leader/researcher
coordination, SwarmRSI-style swarms, RSI-Index and the environment/metrics labs (these last six papers are implemented from the **course's summaries**;
I could not retrieve the papers - see `docs/COURSE_MATERIAL_ISSUES.md`).

## Design choices you should know about (and could be asked about)
* **Quality is not a label.** A patch is good, weak or harmful only because of what its code does on the data. Held-out accuracy is computed on 400 instances no method ever selects on, with a *different category mix* than the dev data (so selection optimism and distribution shift are visible).
* **Matched budgets.** One `Meter` counts instance evaluations for everything, including calibration (Budget RSI), probes (SO-RSI) and H-step probes (Self-HPO).
* **Stub proposer.** Edits are proposed by a stochastic stub, not an LLM. Selection, diagnosis and harness search are real; the proposal distribution is an assumption.
* **Planted blocker.** The SO-RSI base scaffold contains a deliberately plausible-looking bug (`punct_stripper`). Plain naive RSI cannot delete code it did not write, which inflates its gap to SO-RSI; the fair baseline is `naive+blind` (structural moves, no diagnosis).
* **Fresh seeds.** Development used seeds 0-29. Every reported number uses seeds 100-129. I wrote hypotheses H1/H2 (lab 10.05) after seeing development results, and say so in the lab.

## Things that went wrong while building (kept visible on purpose)
* My first Budget RSI and Self-HPO results looked unimpressive; I did **not** tune them. I investigated instead and reported the null results.
* Three bugs in my own simulations, found by reading outliers: infinite no-cost loops (swarm, AReaL); `is_duplicate` flagged a *removal* edit as a no-op, silently blocking the SO-RSI fix; and AReaL-style shared memory lost supported-but-unintegrated findings. Each is fixed and covered by a test or a comment.
* One of my own printed claims (selection optimism grows with number of candidates) contradicted the data and was corrected in lab 10.17.
